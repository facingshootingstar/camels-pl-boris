# Data-driven models at the Storm Boris flood (CAMELS-PL)

Code for the paper *How Well Do Data-Driven Models Reproduce a Record Flood? A Multi-Gauge Out-of-Sample Evaluation on Storm Boris (2024) with CAMELS-PL* (Nguyen Van Trong Hieu, Nguyen Trong Toan, Dang Trang Thanh Su, Ho Le Thien An; FPT University, Ho Chi Minh City).

We train regional LSTMs (two training records × two losses, three seeds each) and LightGBM on CAMELS-PL, compare them with the dataset's benchmark LSTM and HBV, and evaluate the peaks of the September 2024 Storm Boris flood on 73 flood gauges in Poland.

## Data

[CAMELS-PL v1.0.0](https://doi.org/10.5281/zenodo.20133183) (CC BY-NC 4.0). Discharge and water-level data originate from IMGW-PIB; meteorological inputs come from E-OBS v31.0e. The data are not included here: the prep kernel downloads them from Zenodo and checks the MD5 checksum.

## Layout

| Path | What it does |
|---|---|
| `kaggle/prep/prep.py` | Downloads CAMELS-PL and builds `camels_pl.npz` (inputs, discharge, static attributes) plus benchmark CSVs. |
| `kaggle/explore/explore.py` | Initial data exploration. |
| `kaggle/train/train.py` (A) | Base-record LSTMs (NSE and peak-weighted loss) and LightGBM. |
| `kaggle/train_b/train.py` (B) | Long-record LSTMs (1981–2015 without the validation years). |
| `kaggle/train_c/train.py` (C) | Control runs: long record with 3× gradient steps, and 1981–2000 only. |
| `kaggle/diag/diag.py` | Compares Boris with the event that set each gauge's 1981–2015 maximum. |
| `src/merge_outputs.py` | Merges the kernel outputs into `results/kaggle_out/` and checks that every kernel used the same evaluation reference. |
| `src/analyze.py` | Test-period metrics, Boris peak and timing errors, Wilcoxon tests, figures, and `results/numbers.tex`. |
| `src/robustness.py` | Holm adjustment, river-system cluster bootstrap, annual-max controls, runoff coefficients, sensitivity variants, and `results/numbers_rob.tex`. |
| `src/river_systems.csv` | River-system assignment of the 73 flood gauges, used as bootstrap clusters. |
| `src/verify_refs.py` | Resolves every DOI in the bibliography. |
| `results/` | Small result tables (per-gauge metrics and Boris errors, JSON summaries, LaTeX macros). Every number in the paper is read from `numbers*.tex`. |
| `figures/` | Figures generated by `analyze.py`. |

Splits follow the CAMELS-PL benchmark: training 2005-11-01..2015-12-31, validation 2000-11-01..2005-10-31, test 2016-01-01..2024-10-31. The Boris window is 10–30 September 2024.

## Reproducing

1. Push the kernels to your own Kaggle account. Replace `drowningcraft` in each `kernel-metadata.json` with your username. The training kernels use the prep kernel's output as input (`kernel_sources`) and need a GPU.
   ```bash
   kaggle kernels push -p kaggle/prep
   kaggle kernels push -p kaggle/train
   kaggle kernels push -p kaggle/train_b
   kaggle kernels push -p kaggle/train_c
   kaggle kernels push -p kaggle/diag
   ```
2. Download the outputs:
   ```bash
   kaggle kernels output <user>/camels-pl-boris-train -p results/full_A
   kaggle kernels output <user>/camels-pl-boris-train-b -p results/full_B
   kaggle kernels output <user>/camels-pl-boris-train-c -p results/full_C
   kaggle kernels output <user>/camels-pl-boris-diag -p results/diag
   kaggle kernels output <user>/camels-pl-prep -p results/kaggle_prep
   ```
3. Run the local analysis (Python 3.12, see `requirements.txt`):
   ```bash
   pip install -r requirements.txt
   python src/merge_outputs.py
   python src/analyze.py
   python src/robustness.py
   ```

The simulation files (`sim_*.npy`, about 80 MB) are not stored in git. They will be archived on Zenodo with the release.
